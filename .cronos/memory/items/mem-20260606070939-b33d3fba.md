The URL redaction pattern `https://[^@\s]+@github\.com` matches its own replacement string `https://REDACTED@github.com`, causing the PAT guard test to fail with false positives on already-redacted traces. Fix: require a known token prefix before the credential so the replacement cannot re-match. Also: git-ls-files-based scan (not rglob) avoids false positives from historical untracked trace files containing inert rotated PATs.
