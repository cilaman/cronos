# Brief

# Arc 8 — Spaces as Dev Environments: Execution Plan

## Context

Cronos-ready breakdown for **Arc 8** of the
[roadmap](let-s-discuss-key-features-async-hopcroft.md). Arc 8 turns
a Cronos space into a **runnable product**: each space declares a
`dev_runtime` in its metadata, and Cronos can Run / Stop / Restart
the space's dev server as a managed subprocess, allocate
non-colliding port ranges, stream stdout/stderr to a UI log panel,
and poll a `health_url` to surface a clickable link once the server
is up. Custom `kind` is the escape hatch (Cronos just runs your
start/stop scripts). Production is **out of scope** — `prod_url` is
display-only.

There is **no existing** port-allocation, health-poll, or dev-server
code in the backend; those three are genuinely net-new. Everything
else has a pattern to mirror: subprocess lifecycle
([agent.py:203-302](backend/app/agent.py#L203-L302)), pub/sub + SSE
([worker.py:161-178](backend/app/worker.py#L161-L178),
[worker.py:899-1002](backend/app/worker.py#L899-L1002)), space
persistence ([space_storage.py:182](backend/app/space_storage.py#L182)),
and the frontend log/stream stack
([ConversationStream.tsx](frontend/src/components/ConversationStream.tsx),
[useLiveStream.ts:147-227](frontend/src/hooks/useLiveStream.ts#L147-L227)).

**Prerequisite:** Arc 1 (task `type` + `parent_id` hierarchy) — done.

## Execution model

One umbrella **Goal** `Arc 8 — Spaces as dev environments`, holding
**four nested subgoals**. Each subgoal is implemented as a **CC-v1
pipeline** scaffolded via `/pipeline-scaffold`, i.e. the seven-phase
DAG:

```
scout → analysis → design → impl → test ─┐
                              └───────────┴→ review → doc
```

The per-subgoal `request_text` blocks below are fed **verbatim** to
`/pipeline-scaffold`; the pipeline's own analyst/architect decompose
them into requirements + iterations, and its **test + review phases
are the quality gate** (no separate `test-architect` step).

**Single shared branch.** All four subgoals nest under the umbrella,
so each impl phase's `/goal-branch-setup` resolves the *root* goal =
umbrella and every commit lands on one `feature/{umbrella-slug}`
branch. Merge to `main` happens **once**, at the end (see Standing
rules → Finalize override).

**Dependency chain** (serialized on the shared branch):

| SG | Title | scout `depends_on` |
|----|-------|--------------------|
| SG1 | `dev_runtime` schema + port allocator | — |
| SG2 | process manager + health poller | SG1 · doc |
| SG3 | dev-runtime REST API + SSE logs | SG2 · doc |
| SG4 | frontend panel + sidebar running dot | SG3 · doc |

## SG1 — `dev_runtime` schema + port allocator

**Title:** `Arc 8/SG1 — dev_runtime space schema + port allocator`

**`request_text` (verbatim to `/pipeline-scaffold`):**

> Add a `dev_runtime` config to space metadata plus a per-space port
> allocator. **No process spawning in this subgoal** — schema,
> persistence, and port reservation only.
>
> **Schema.** Extend the `Space` Pydantic model
> ([models.py:120-152](backend/app/models.py#L120-L152)) with
> `dev_runtime: DevRuntime | None = None` and
> `prod_url: str | None = None`. New nested model `DevRuntime`:
> `kind: Literal["docker-compose","npm","python","custom"]`,
> `command: str | None`, `start_script: str | None`,
> `stop_script: str | None`, `health_url: str | None`,
> `ports: list[int] = []`. Validator: `kind="custom"` requires
> `start_script` + `stop_script`; any other `kind` requires
> `command`. `health_url` optional.
>
> **Persistence (YAML).** `dump_space`
> ([space_storage.py:182-198](backend/app/space_storage.py#L182-L198))
> builds an **explicit dict** — add `dev_runtime` + `prod_url` there
> or they are silently dropped on save. `parse_space_yaml`
> ([space_storage.py:153-165](backend/app/space_storage.py#L153-L165))
> must round-trip them. Add a `set_dev_runtime(space_id, cfg)`
> mutator mirroring `set_autopilot`
> ([space_storage.py:434-454](backend/app/space_storage.py#L434-L454)):
> lock → `model_copy(update=...)` → `atomic_write`
> ([storage.py:346-351](backend/app/storage.py#L346-L351)).
>
> **Port allocator.** New `backend/app/dev_runtimes.py` (allocator
> only this subgoal): `allocate_ports(space_id, count) -> list[int]`
> returns a disjoint block, **persisted** and **non-colliding across
> spaces** when several run at once; `release_ports(space_id)` frees
> them. Base port via env `CRONOS_DEV_PORT_BASE` (default 5300),
> fixed block size per space. Deterministic per space id. If the
> config declares explicit `ports`, honor them but still reserve to
> prevent cross-space collision.
>
> **Acceptance:** a space with `dev_runtime` + `prod_url`
> round-trips through `dump_space`/`parse_space_yaml`; two distinct
> spaces receive disjoint port blocks; `kind=custom` without scripts
> is rejected; non-custom without `command` is rejected; releasing a
> space frees its ports for reuse.

## SG2 — process manager + health poller

**Title:** `Arc 8/SG2 — dev runtime process manager + health poller`

**`request_text` (verbatim to `/pipeline-scaffold`):**

> Build the `DevRuntimeManager` core in
> `backend/app/dev_runtimes.py` (extends SG1's allocator). Keyed by
> `space_id`; mirrors the agent subprocess pattern. **No HTTP API or
> UI in this subgoal.**
>
> **Lifecycle.** `start(space_id)` / `stop(space_id)` /
> `restart(space_id)`. Spawn with
> `asyncio.create_subprocess_exec` mirroring `run_agent`
> ([agent.py:254-260](backend/app/agent.py#L254-L260)), `cwd =
> space_dir(space_id)`
> ([space_storage.py:659-669](backend/app/space_storage.py#L659-L669)),
> env inheriting + the allocated ports. **Net-new:** pass
> `start_new_session=True` so the whole process group can be killed
> (dev servers fork children — `run_agent` does not do this).
> Command resolution: `kind != custom` runs `command`;
> `kind=custom` runs `start_script` (stop via `stop_script`).
>
> **Status.** Track `stopped | starting | running | healthy |
> unhealthy | exited | error` per space (registry dict modeled on
> `WorkerPool._workers`,
> [worker_pool.py:39](backend/app/worker_pool.py#L39)).
>
> **Log capture + pub/sub.** Capture stdout/stderr into a bounded
> ring buffer (mirror `drain_stderr`,
> [agent.py:269-283](backend/app/agent.py#L269-L283)) and a stdout
> read loop ([agent.py:344-375](backend/app/agent.py#L344-L375))
> that does **not** block on EOF (see the comment at
> [agent.py:337-343](backend/app/agent.py#L337-L343) — dev servers
> keep the pipe open). Fan lines out to subscribers via a
> `subscribe(space_id)`/`_publish` pair mirroring
> [worker.py:161-178](backend/app/worker.py#L161-L178) +
> [worker.py:899-930](backend/app/worker.py#L899-L930) (replay
> buffer + drop-oldest backpressure).
>
> **Stop/restart.** SIGTERM the process group → wait 2s → SIGKILL
> (mirror `kill_on_cancel`,
> [agent.py:285-302](backend/app/agent.py#L285-L302)) using
> `os.killpg`. `restart` = stop then start.
>
> **Health poller.** Per running runtime, an async task GETs
> `health_url` every `CRONOS_DEV_HEALTH_INTERVAL_S` (default 3):
> 200 → `healthy` and record the URL; non-200/exception →
> `unhealthy`; stop polling on process exit. Skip if no `health_url`.
>
> **Shutdown.** `stop_all()` mirroring `WorkerPool.stop_all`
> ([worker_pool.py:132-143](backend/app/worker_pool.py#L132-L143)).
>
> **Acceptance** (unit, mocked subprocess + health client): `start`
> spawns with correct cmd/cwd/env and `start_new_session=True`;
> stdout lines are captured and replayed to a subscriber; the health
> poller flips `running → healthy` on a mocked 200; `stop`
> terminates the process group; `restart` = stop then start; two
> managers on different spaces don't collide on ports.

>   `{state, pid, ports, health, url}`.

>

> [spaces.py:46-55](backend/app/api/spaces.py#L46-L55). Return 404

> ([spaces.py:130-148](backend/app/api/spaces.py#L130-L148)):

> `": ok\n\n"`, drain the replay buffer, stream live

> `event: end` on process exit.
>
> **Acceptance:** `start` returns 200 with `state=running`; `status`
> reflects state + ports + health; `stream` emits captured log lines
> then `end` on stop; `stop` returns 200/204; `start` on a space
> without `dev_runtime` → 404; `start` twice → 409.
