## Root cause: Memory retrieval is implemented but never wired in

Here's what I found in the codebase:

**Three bugs preventing memory from accumulating:**

1. **`run_agent` doesn't forward memory to the prompt** (`agent.py:208–225`)  
   `build_prompt()` accepts a `memory_items` parameter but `run_agent()` always calls it with just `(task, user_message, goal_context)` — the memory slot is never passed through.

2. **`memory_retrieval.retrieve()` is never called** (`worker.py:262`)  
   The retrieval function exists and is fully implemented, but it's never imported or invoked anywhere in the worker. No memory context is retrieved before any agent run.

3. **Goal children's MEMORY: blocks are silently discarded** (`worker.py:590–652`)  
   When a goal runs child tasks, `_finalize_child()` handles the result but has no code to parse/save MEMORY: blocks — unlike the standalone-task path in `_finalize()` which does.

**The fix is three targeted changes:**

- **`agent.py`**: Add `memory_items: list[MemoryItem] | None = None` to `run_agent()`, pass it to `build_prompt()`
- **`worker.py`**: Import `memory_retrieval`, call `retrieve()` before each `run_agent()` call in both `_run_task` and `_run_goal`, pass result as `memory_items`
- **`worker.py`**: Add MEMORY: block parsing to `_finalize_child()` (same 12 lines already in `_finalize()`)

No schema changes, no new files — just wiring together code that already exists.
