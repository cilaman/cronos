# Brief

# Arc 6 — Harnesses (Visual Agent Workflows)

A **Harness** is a DAG executed by Cronos: authors compose nodes on a visual
canvas, Cronos runs the DAG, and a live overlay animates execution.

## Node types

- **Agent** — run a registered agent/skill with a prompt template + variable bindings.
- **Trigger** — manual / cron / event (task-state, webhook, file change, inter-node message).
- **Decision** — branch on STATUS, output regex, or variable compare.
- **Wait** — human / time / upstream signal.
- **Aggregator** — join N upstreams; emit on all (or any).

## Persistence

Each Harness is YAML at `{space}/.cronos/harnesses/<name>.yml` (markdown-as-truth);
editor + runtime read it, editor writes it.

## Runtime

A run is a first-class Task (`type=goal`) with one child task per Agent node (reusing
Arc 1 hierarchy + worker model). Each step's trace links to the run via `parent_run_id`.
Control-flow nodes are evaluated in-process by a new interpreter — not `_run_goal`.

## Editor (UI)

React Flow, Cronos paper/ink palette. Differentiator = a live-execution overlay:
active node pulses, completed edges thicken, failed paths desaturate; click a node
→ its agent's live log (ConversationStream.tsx).
