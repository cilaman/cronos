### Why `memory_injected` is always 0

`_memory_injected_for_workspace()` in `worker.py:61` looks for files in the workspace-specific Claude memory dir. Those files are written DURING a run, so the dir is always empty at run start. The function correctly returns `[]` — but this makes `memory_hit_rate` (`used / max(1, injected)`) meaningless since the denominator defaults to 1.

---

### Space-scoped MemoryItems: injected but broken (just fixed)

The `retrieve()` call DOES run and DOES pass items to `build_prompt()`. The ref_counts prove it — median 131, max 198 across 217 items — because `store.get()` increments `ref_count` for every candidate evaluated per run.

Three bugs degraded their usefulness until commit `80f4fc1` (2026-06-18):

1. **`boost()` was multiplicative** (`score × 1.2`): a score of 0.0 × 1.2 = 0.0. New items could never climb from 0. Result: 205 of 217 items stuck at `score=0.0`.

2. **`MemoryStore.get()` skipped `decay()`**: scores never aged before being boosted. The decay/boost pipeline was broken at the call site (`memory_store.py:248`).

3. **`build_prompt()` injected only the first line** of `item.body`. Agents saw truncated one-liners instead of full context.

All three fixed in the merge landed today (`0da02ae`). The 12 items at `score=10.0` are the ones whose scores somehow survived the multiplicative bug (they were initialized > 0 before the bug was introduced and accessed enough to reach cap).

---

### Assessment

**Claude Code project memory (MEMORY.md + topic files):** Actively useful. 43 reads of the index in 30 days confirms agents regularly consult it for project orientation. Specific files are looked up when agents need procedure or state details.

**Space-scoped MemoryItems:** Were being retrieved and injected on every run, but with three bugs that made them nearly useless in practice (score=0 items ranked by coverage score, truncated bodies). The fix landed today — effectiveness is unmeasured for now.

**`memory_hit_rate` metric:** Currently broken as a metric (always ÷1 instead of ÷injected_count). The denominator should include retrieved MemoryItems, not just workspace-dir files.
