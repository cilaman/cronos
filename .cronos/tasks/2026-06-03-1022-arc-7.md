# Brief

# Arc 7 — Inter-agent Messaging: Execution Plan (CC-v1 pipelines)

## Context

Arc 7 of the [roadmap](let-s-discuss-key-features-async-hopcroft.md):
give agent runs an asynchronous **mailbox** so one run can hand a
structured message to another and the recipient wakes on delivery.
Smallest viable mechanism — in-process broker, file-backed mailboxes,
two new agent tools (`SendMessage` / `ReadInbox`), wake-on-delivery,
messages replayable in the trace.

**Why now:** Arcs 1 (hierarchy), 4 (autopilot/PR flow) are merged.
Arc 5b (adopted-tool mounting) and Arc 6 (harnesses) are **not built**,
so Arc 7 ships **standalone**: tools mounted directly into every run
(not via adoption); verified with two standalone tasks messaging each
other (not harness `Wait` nodes). Integration hooks stay clean for 5/6.

**Locked decisions** (carry verbatim into every pipeline request so the
scout/analyst/architect do not re-litigate them):

- **Tool exposure = MCP stdio server.** A backend-bundled stdio MCP
  server exposes `SendMessage`/`ReadInbox`; `agent.py` writes a per-run
  `--mcp-config` and adds the tool names to `--allowedTools`. No Skill
  detour. (agent.py today: tool consts at
  [agent.py:132-133](backend/app/agent.py#L132-L133), allowlist+add-dir
  at [agent.py:223-247](backend/app/agent.py#L223-L247) — no MCP yet.)
- **Mailbox = file-as-truth.** One atomic JSON per message under
  `{space}/.cronos/mailboxes/<task_id>/<msg_id>.json`, mirroring
  [trace_store.py](backend/app/trace_store.py) tmp→rename writes.
- **Addressing:** `agent://<space_id>/<task_id>` (standalone-task form;
  harness/node form deferred to Arc 6).
- **Reuse the existing delivery substrate.** `Task.pending_messages`
  + `apply_reply`/`drain_pending`/`append_pending`
  ([storage.py:828,905,925](backend/app/storage.py#L828)), the worker
  event bus `_publish`/`subscribe` + `on_idle`/`enqueue`
  ([worker.py:108,139,222](backend/app/worker.py#L139)), and the
  `/api/tasks/{id}/stream` SSE the frontend already consumes
  (`useLiveStream`). The mailbox is the structured store; a short
  `pending_messages` poke ("📬 message from <addr>: <subject>") is how
  a non-active recipient is woken to call `ReadInbox`.
- **Branch:** `feature/arc-7-messaging`, created from `main` if missing.
  No merge to `main` until the arc lands (manual).

## S1 — Mailbox store + in-process broker + API

**Title:** `Arc 7/S1 — Mailbox broker + persistence + API`
**Slug:** `arc7-mailbox-broker` · **has_ui:** no

**Pipeline request:** New `backend/app/messaging.py`:
- `Message` Pydantic model: `id, from_addr, to_addr, subject, body,
  payload: dict, created_at, delivered_at: datetime|None,
  read_at: datetime|None`.
- `MessageStore` — file-as-truth: one atomic JSON per message under
  `{space}/.cronos/mailboxes/<task_id>/<msg_id>.json` (reuse the
  tmp→rename `atomic_write` pattern from
  [trace_store.py](backend/app/trace_store.py)). Methods: `save(msg)`,
  `inbox(space_id, task_id, unread_only=False) -> list[Message]`
  (order-stable by `created_at`), `mark_read(space_id, task_id, msg_id)`.
- `MessageBroker` — in-process singleton: `send(msg)` resolves the
  `agent://` address, persists via `MessageStore`, then publishes a
  `message` event onto the worker event bus so subscribers update live.
  Address parse/format helpers `parse_addr`/`format_addr`.

New `backend/app/api/messaging.py` (registered in
[main.py:237](backend/app/main.py#L237) like the other routers):
- `POST /api/messages/send` body `{to, subject, body, payload}` → 201
  with the stored `Message` (sender resolved from request context;
  explicit `from` allowed for manual/testing sends).
- `GET /api/spaces/{id}/tasks/{task_id}/inbox?unread=<bool>` → messages.
- `POST /api/spaces/{id}/tasks/{task_id}/inbox/{msg_id}/read` → 204.

**Scope files:** `backend/app/messaging.py` (new),
`backend/app/api/messaging.py` (new), `backend/app/main.py` (router
registration only).

**Acceptance:** `send` writes one JSON + returns it; `inbox` lists it
order-stably; `unread` filter + `mark_read` flips `read_at`; broker
publishes a `message` event observable via the worker bus. Invalid
`agent://` address → 422.

## S2 — `SendMessage` / `ReadInbox` MCP tools mounted into runs

**Title:** `Arc 7/S2 — MCP mail tools + mount into agent runs`
**Slug:** `arc7-agent-mail-tools` · **has_ui:** no · **depends_on:** S1

**Pipeline request:** New `backend/app/messaging_mcp.py` — a stdio MCP
server (entry `python -m app.messaging_mcp`) exposing two tools that
proxy the S1 HTTP API for the **current run's task**:
- `SendMessage(to, subject, body, payload)` → `POST /api/messages/send`.
- `ReadInbox(unread_only=true)` → `GET …/inbox`, returns structured
  messages. It reads `CRONOS_API_BASE`, `CRONOS_TASK_ID`,
  `CRONOS_SPACE_ID` from env to fill `from`/inbox addressing.

Wire into [agent.py:223-247](backend/app/agent.py#L223-L247):
- Write a per-run `.mcp.json` into the workspace describing the
  `cronos` stdio server; pass `--mcp-config <path>`.
- Append `mcp__cronos__SendMessage,mcp__cronos__ReadInbox` to **both**
  [PLAN_MODE_TOOLS and DEFAULT_TOOLS](backend/app/agent.py#L132-L133)
  in the `--allowedTools` value.
- Inject `CRONOS_API_BASE`/`CRONOS_TASK_ID`/`CRONOS_SPACE_ID` into the
  subprocess env (the local API base + the running task/space).

**Scope files:** `backend/app/messaging_mcp.py` (new),
`backend/app/agent.py` (tool consts, command builder, env injection).

**Acceptance:** a `run_agent` unit test asserts the built command
includes `--mcp-config` and the two `mcp__cronos__*` tool names, and the
env carries the task/space ids; the MCP server's `SendMessage` round-trips
through the S1 API into a recipient mailbox; `ReadInbox` returns it.

## S3 — Wake-on-delivery + message trace persistence

**Title:** `Arc 7/S3 — Wake-on-delivery + replayable message trace`
**Slug:** `arc7-wake-and-trace` · **has_ui:** no · **depends_on:** S1, S2

**Pipeline request:** Make delivery wake an idle recipient and make
messages replayable.
- **Wake-on-delivery:** on `MessageBroker.send`, look up the recipient
  task; if it is **not** currently active, `append_pending` a
  human-readable poke (`📬 message from <from_addr>: <subject> — call
  ReadInbox`) and `enqueue` it on its space worker (reuse
  [storage.py:925](backend/app/storage.py#L925),
  [worker.py:139](backend/app/worker.py#L139)). If active, the message
  simply lands in the mailbox for the next `ReadInbox`. Route through a
  small worker hook so the broker stays transport-agnostic; the existing
  [`on_idle`](backend/app/worker.py#L222) path drains pending as today.
- **Trace persistence:** extend `RunTrace` in
  [trace_parser.py:110-140](backend/app/trace_parser.py#L110-L140) with
  `messages_sent: list[...]` / `messages_received: list[...]` (id, addr,
  subject, ts), populated when a run's `SendMessage`/`ReadInbox` tool
  calls are parsed from the stream. Persisted in the run JSON via
  [trace_store.py](backend/app/trace_store.py) → replayable.

**Scope files:** `backend/app/worker.py`, `backend/app/messaging.py`
(broker→worker hook), `backend/app/trace_parser.py`,
`backend/app/trace_store.py` (only if a schema bump is needed).

**Acceptance:** sending to a `backlog`/`waiting` task enqueues it with a
`pending_messages` poke and it transitions to `active`; sending to an
already-active task does not double-enqueue; a run that called the mail
tools has non-empty `messages_sent`/`messages_received` in its persisted
trace.
